# Paragraph breaks (both apps)

Written 2026-10-24 for B-40 (desktop) and B-40a (Android). (V) = verified, (I) = inferred.

The *Paragraphs* finishing step (research: [`research/post-processing/README.md`](../research/post-processing/README.md),
"Paragraph model format") splits a finished take into paragraphs with a small word-level classifier.
It only ever joins the take's words with a space or a blank line, so it cannot change the text.
This file is the one specification both apps implement; [`paragraph-cases.json`](paragraph-cases.json)
is the shared test file, generated by the reference implementation.

## Algorithm

1. **Words:** split the take's text on whitespace (any Unicode whitespace run). No words: return
   the text unchanged.
2. **WordPiece per word**, each word tokenized on its own, no special tokens. BERT uncased rules
   (the `tokenizer.json` is `BertNormalizer{clean_text, handle_chinese_chars, lowercase,
   strip_accents: null}` + `BertPreTokenizer` + `WordPiece{"##", max 100 chars, [UNK]}`):
   - clean: drop U+0000, U+FFFD and control characters (category Cc/Cf, except `\t \n \r`, which
     count as whitespace); map whitespace to a space.
   - put spaces around CJK ideographs (the BERT `_is_chinese_char` ranges).
   - lower-case, then strip accents: NFD, drop category Mn (`São` → `sao`, `naïve` → `naive`).
   - split on whitespace, then split off every punctuation character as its own piece. Punctuation
     = ASCII 33–47, 58–64, 91–96, 123–126, or Unicode category P*. Currency and other symbols
     (`₪`, `€`, emoji) are **not** punctuation: `₪1,200!` → `₪1` `,` `200` `!`.
   - WordPiece each piece greedily, longest match first, continuation pieces prefixed `##`. A piece
     longer than 100 characters, or with any part not in the vocabulary, becomes `[UNK]` (id 100)
     as a whole (`₪1` → `[UNK]`).
   - a word that produces no ids at all (it was only control characters) gets `[UNK]`.
   `vocab.txt`: line *n* (from 0) is id *n*; `[PAD]` 0, `[UNK]` 100, `[CLS]` 101, `[SEP]` 102.
3. **Windows** of at most 510 tokens, cut at word boundaries (`windows()` in the reference):
   starting at word `w0`, take words while the window's token count stays <= 510 (always at least
   one word); the next window starts at the first word whose token offset is >= offset(`w0`) + 256,
   but no later than the current window's end and at least `w0 + 1`. Stop when a window reaches
   the last word.
4. **Run** each window as `[CLS] pieces… [SEP]`, attention mask all ones. A word's score is
   softmax(logits)[1] at its **first** sub-token. When several windows cover a word, take the
   window where that token is closest to the middle (`|position − (len − 1) / 2|` smallest; on a
   tie, the earlier window).
5. **Join:** the first word never starts a paragraph. Every later word with score >=
   `paragraph_threshold` (from the manifest or `config.json`) starts one: `"\n\n"` before it, a
   single space before every other word.

The output differs from the input only in whitespace; check that (squash whitespace, compare) and
return the input if it ever fails.

## Where it runs

- The step needs the **whole take**, so it applies only when the text is inserted in one go: insert
  / type as you go off, the File / Transcribe tab, Transcription Mode, Paste last. With insert as you
  go on, pieces are already in the field; the setting does nothing for that take (the UI says so).
- Order: after the per-piece stages (personal dictionary, disfluency chop, ALL CAPS), on the joined
  take. History stores the paragraphed text.
- Off by default. Turning it on downloads the model (34 MB) once; if the model is missing or fails
  to load, the take is inserted unparagraphed, never lost.
- Inserting a blank line: the desktop's typing backend and the Android overlay must deliver `\n`
  as a line break (see `docs/debug-log/2026-10-23-overlay-eats-line-break.md` for the overlay's
  SET_TEXT path).

## Parity test

[`paragraph-cases.json`](paragraph-cases.json): 11 cases (empty, one word, unicode/accents/currency/
emoji/CJK/romanised Hebrew, a 120-character word, control characters, the "Hi John" greeting, three
test memos, and the longest test memo, which needs 2 windows). Each has `word_pieces` and `windows`
(must match exactly), `probs_int8` (from `model_int8.onnx` on x86-64 with onnxruntime 1.31: compare
with tolerance 0.02, since int8 kernels differ by CPU and ONNX Runtime version), and `output`
(compare when no score is within 0.02 of the threshold). Regenerate it with `uv run scripts/paragraph_cases.py` (reference code
and model from the Hub) if the model version changes.

Latency (I, laptop x86 CPU, 1 thread): about 0.65 s for a 340-word take with int8. Phone: not
measured yet.
